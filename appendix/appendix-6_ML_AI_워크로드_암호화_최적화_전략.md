# 부록 6 - ML/AI 워크로드 암호화 최적화 전략

## 🚀 1) WireGuard 우선 사용 — ML/AI 워크로드의 기본 선택

ML/AI 워크로드는 다음 특성 때문에 **IPsec보다 WireGuard가 훨씬 유리**

- GPU 노드에서 CPU 오버헤드가 적어야 함
- 대규모 모델 파일 전송 시 암호화 비용이 커짐
- WAN 환경에서 빠른 암호화/복호화 필요

WireGuard는 커널 공간에서 동작하고 암호화 알고리즘이 단순해서 **IPsec 대비 20~40% 정도 더 빠른 경우가 많음**.

### 전략

- ML/AI 클러스터는 **WireGuard를 기본값으로 설정**
- 규제 산업이나 기존 보안 장비 통합이 필요할 때만 IPsec 고려

## ⚙️ 2) GPU 노드에서 암호화 부하 최소화

GPU 노드는 ML/AI 클러스터의 핵심 자원이기 때문에 **암호화로 CPU가 리소스를 사용하면 전체 성능이 떨어짐**

### 전략

- GPU 노드에서는 **암호화된 트래픽을 최소화**
- 외부로 나가는 트래픽은 **Egress Gateway 노드로 우회**
- GPU 노드는 내부 east-west 트래픽만 처리
- 암호화는 CPU가 여유 있는 일반 노드에서 수행

이렇게 하면 GPU 노드의 CPU가 암호화 때문에 낭비되지 않게 됨

## 📡 3) 대규모 모델 전송 최적화 — BIG TCP + BBR + 암호화 조합

ML/AI 워크로드는 TB 단위 모델 파일을 외부에서 가져오거나 노드 간 전송하는 경우가 많음.

암호화가 켜져 있으면 패킷 수가 많아질수록 CPU 부하가 커지기 때문에, **패킷 수 자체를 줄이는 최적화가 필수**.

### 전략

- **BIG TCP 활성화**
→ 대형 패킷으로 암호화/복호화 횟수 감소
- **BBR 혼잡 제어 활성화**
→ WAN 환경에서 대역폭 활용 극대화
- **XDP 기반 fast-path 사용 가능 시 적용**
→ 암호화 전 단계에서 불필요한 패킷 드롭

이 조합은 모델 다운로드/업로드 속도를 크게 개선할 수 있슴

## 🔐 4) 암호화 + 네트워크 정책 결합으로 불필요한 트래픽 제거

암호화는 CPU를 사용하기 때문에 **암호화할 필요 없는 트래픽은 애초에 차단하는 게 성능 최적화의 핵심**

### 전략

- ML/AI 워크로드는 **필요한 서비스 간 통신만 허용**
    - model-server → feature-store
    - trainer → parameter-server
    - inference → redis
- 나머지 lateral movement는 모두 차단
- Egress는 FQDN 기반으로 필요한 도메인만 허용
    - `huggingface.co`
    - `.s3.amazonaws.com`
    - `api.openai.com`

암호화할 트래픽 자체가 줄어들기 때문에 성능이 올라감

## 🧠 5) 멀티클러스터 ML/AI 환경에서 암호화 최적화

ML/AI는 멀티클러스터 구조가 흔함

- 지역별 GPU 클러스터
- 데이터 레이크 클러스터
- 모델 서빙 클러스터

이때 암호화가 켜져 있으면 클러스터 간 통신이 병목이 될 수 있슴

### 전략

- **Cluster Mesh + WireGuard 조합**
→ 클러스터 간 암호화 성능 최적화
- **지역 간 트래픽은 Gateway API로 L7 제어**
→ 불필요한 cross-region 암호화 트래픽 제거
- **대규모 데이터 전송은 L4 경로로 우회**
→ L7 프록시를 거치지 않게 해서 암호화 부하 감소

## 📊 6) 암호화 트래픽 관측 — Hubble로 병목 지점 찾기

암호화가 켜져 있으면 병목이 어디서 생기는지 파악하기 어려움.

### 전략

- Hubble로 암호화된 flow를 추적
- GPU 노드에서 암호화 CPU 사용량 모니터링
- cross-node 전송 지연(latency) 분석
- 외부 API 호출 시 암호화로 인한 RTT 증가 확인

이걸 기반으로 WireGuard/노드 배치/트래픽 경로를 조정하면 성능이 크게 개선됨.

## 📝 최종 요약

ML/AI 워크로드에서 Transparent Encryption을 최적화하려면 다음 6가지 전략이 핵심

1. **WireGuard 우선 사용**
2. **GPU 노드에서 암호화 부하 최소화**
3. **BIG TCP + BBR로 대규모 모델 전송 최적화**
4. **암호화 + 네트워크 정책 결합으로 불필요한 트래픽 제거**
5. **멀티클러스터 환경에서 암호화 경로 최적화**
6. **Hubble로 암호화 트래픽 병목 분석**

이 조합을 적용하면
ML/AI 클러스터의 **보안·성능·운영 안정성**을 모두 만족시키는 암호화 아키텍처가 구축 가능
