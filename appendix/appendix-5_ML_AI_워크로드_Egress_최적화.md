# 부록 5 - ML/AI 워크로드 Egress 최적화

## 🚀 1) ML/AI 워크로드의 Egress 특성

ML/AI 환경은 일반 애플리케이션과 다르게 Egress 트래픽이 다음과 같은 특징이 있슴

- **대규모 모델 다운로드/업로드**
HuggingFace, S3, GCS 등으로 TB 단위 전송이 발생
- **외부 API 호출 빈도 높음**
OpenAI, Vertex AI, AWS Bedrock 등
- **GPU 노드에서 외부로 나가는 트래픽 집중**
학습/추론 노드가 특정 외부 서비스와 지속적으로 통신
- **비용·보안·규제 민감**
외부 API 호출 비용이 크고, 데이터 유출 위험도 존재

그래서 ML/AI 워크로드는 **일반적인 Egress 정책보다 훨씬 정교한 제어와 최적화가 필요**.

## 🔥 2) 핵심 전략 1 — Egress Gateway로 트래픽 중앙화

### 왜 중요한가?

ML/AI 워크로드는 외부로 나가는 트래픽이 많아서,
각 Pod가 제각각 외부로 나가면 다음 문제가 발생함

- NAT IP가 분산되어 감사·추적이 어려움
- 방화벽 규칙을 모든 노드에 적용해야 해서 운영 복잡
- GPU 노드가 외부 트래픽으로 과부하될 수 있음

그래서 **Egress Gateway 노드를 따로 두고 모든 외부 트래픽을 그쪽으로 우회**시키는 게 좋음.

### 효과

- NAT IP 고정 → 감사·추적·규제 대응
- 방화벽·프록시·보안 장비와 쉽게 연동
- GPU 노드의 네트워크 부하 감소
- 외부 API 호출 비용 분석이 쉬워짐

## 🔐 3) 핵심 전략 2 — FQDN 기반 Egress 정책으로 외부 API 접근 제어

ML/AI 워크로드는 특정 외부 서비스만 접근해야 하는 경우가 많음

- HuggingFace 모델 다운로드
- S3/GCS 데이터 접근
- OpenAI/Anthropic API 호출
- GitHub 모델 코드 가져오기

이때 **FQDN 기반 Egress 정책**을 사용하면 다음이 가능함

- `huggingface.co`만 허용
- `api.openai.com`만 허용
- `.s3.amazonaws.com`만 허용
- 나머지 모든 외부 접근 차단

### 효과

- 데이터 유출 위험 감소
- 비용 통제
- 규제 준수
- 팀별 외부 접근 분리

## ⚙️ 4) 핵심 전략 3 — 대규모 모델 전송을 위한 네트워크 성능 최적화

ML/AI 워크로드는 TB 단위 모델 파일을 외부에서 가져오거나 업로드하는 경우가 많으므로
Cilium의 다음 기능을 활용하면 성능이 크게 향상됨.

### 1) BIG TCP 활성화

- 대형 패킷 전송으로 대역폭 효율 증가
- 모델 다운로드 속도 향상

### 2) BBR 혼잡 제어

- WAN 환경에서 대역폭 활용 극대화
- 클라우드 간 모델 전송 시 효과 큼

### 3) eBPF 기반 NAT

- 커널 레벨 NAT → CPU 오버헤드 감소
- GPU 노드의 네트워크 병목 제거

## 🧠 5) 핵심 전략 4 — 팀/워크로드별 Egress 분리

ML/AI 조직은 팀별로 사용하는 외부 서비스가 다르기 때문에
Egress 정책을 팀 단위로 분리하는 것이 좋음

### 예시

- **ML팀** → HuggingFace, OpenAI
- **데이터팀** → S3, GCS
- **플랫폼팀** → GitHub, Docker Hub

### 효과

- 팀별 비용 추적
- 팀별 보안 정책 분리
- 사고 발생 시 영향 범위 최소화

## 🛡️ 6) 핵심 전략 5 — GPU 노드 보호

GPU 노드는 ML/AI 클러스터의 핵심 자원이기 때문에
외부 트래픽으로 GPU 노드가 과부하되면 전체 성능이 떨어짐.

### 해결책

- GPU 노드에서는 **직접 외부로 나가지 않도록**
- 모든 외부 트래픽은 **Egress Gateway 노드로 우회**
- GPU 노드는 내부 통신만 담당

## 📊 7) 핵심 전략 6 — 관측성(Hubble)로 외부 트래픽 분석

ML/AI 워크로드는 외부 API 호출 비용이 크기 때문에
Egress 트래픽을 관측하는 것이 매우 중요.

### Hubble로 가능한 것

- 어떤 Pod가 어떤 외부 도메인에 얼마나 호출했는지
- 외부 API 호출 실패율
- 모델 다운로드 속도 병목 지점
- 팀별 외부 트래픽 사용량

## 📝 최종 요약

ML/AI 워크로드에서 Egress 최적화는 다음 6가지 전략으로 정리됨

1. **Egress Gateway로 외부 트래픽 중앙화**
2. **FQDN 기반 정책으로 외부 API 접근 제어**
3. **BIG TCP + BBR로 대규모 모델 전송 최적화**
4. **팀/워크로드별 Egress 분리**
5. **GPU 노드 보호(외부 트래픽 우회)**
6. **Hubble로 외부 트래픽 관측 및 비용 분석**

이 조합을 적용하면 ML/AI 클러스터의 **성능·보안·비용·규제 대응**을 모두 만족시키는 Egress 아키텍처가 가능함
